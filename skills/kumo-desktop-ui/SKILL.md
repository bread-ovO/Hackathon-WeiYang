# Kumo 桌面界面

使用真实 Kumo 组件，保留其键盘、焦点和可访问性行为，在项目边界封装业务语义。不要仅复制颜色并声称已经接入组件库。

## 先查版本和组件 API

查看目标应用 package.json 与锁文件。以已安装包的类型声明、CLI 输出为准；官网 main 可能领先于当前依赖。没有安装时查官方安装文档并根据项目的 React 版本选择版本，不自动升级既有依赖。

从包所在项目运行 `pnpm exec kumo ls` 与 `pnpm exec kumo doc Button`；在本事项助手仓库也可使用：

```sh
node apps/desktop/node_modules/@cloudflare/kumo/bin/kumo.js doc Button
```

按需查询 Input、Badge、Dialog 等具体组件，不一次加载所有文档。官方来源和样式集成方式见 [references/integration.md](references/integration.md)。

## 封装方式

- 优先按组件路径导入，如 `@cloudflare/kumo/components/button`，减少无关图表和代码展示依赖。
- 薄封装负责统一默认 variant、尺寸、状态映射和业务布局；透传原组件 props 与 ref。保持 disabled、loading、aria 标签与表单行为。
- 普通按钮明确 `type="button"`；提交按钮明确 `type="submit"`。输入保持标签关联。
- Dialog 使用匹配版本的受控 Root、内容、Title 与 Description，保留焦点约束。程序打开且没有 Trigger 时，验证关闭后焦点回到合理的入口。
- 数据状态与视觉状态分开。状态 Badge 只表达领域结果，不自行推断完成。

## 视觉适配

采用 Kumo 语义色变量区分底层、面板、边线、正文和状态；尽量避免在组件内部覆盖主题私有变量。正文和主要操作优先 14px，次要元信息可按项目密度使用 11–12px；这是桌面项目的适配，不是对 Cloudflare 官方规范的逐字执行。标题使用中等/半粗字重，避免人为压缩字距。

圆角跟随容器层级；很小间距的嵌套圆角保持同心。阴影面板可用 ring/outline 或 box-shadow 表示边线，避免额外 border 改变布局尺寸。悬停颜色不做拖慢反馈的渐变。不要以低对比、小文字取代信息层级。

**事项助手特定约定**：菜单作为整个窗口的中性灰底层，右侧工作区是留有外边距的白色圆角面板，圆角裁剪其内部内容。菜单与工作面板不可重新合成左右无缝平铺。布局间距优先使用 4、8、12、16、24、32px，采用紧凑密度；主要内容左侧统一 16px，列表行上下 12px。边线保留 1px，不为凑偶数加粗。字体大小不随间距机械缩小。这一约定仅适用于本项目和明确要求此结构的界面；其他项目遵循用户自己的布局要求。

## 验证

根据改动验证实际窗口中的圆角、溢出与阅读层级，包含一个宽窗口和一个窄窗口。测试组件替换影响的关键交互，尤其是弹窗打开/提交/取消/Escape、键盘焦点和禁用状态。Electron 中验证打包 CSS 与离线加载，不为修复样式去放宽 CSP 或 preload 权限。

本项目的示例数据不能写入真实数据库，连接尚未接入时继续显示真实空态。交付时区分视觉完成、可交互示例和已经接入的业务能力。
