# BUGU：提交 PR 并反馈链接（D04 场景冻结）

本轮需求：D04、A04、A05、V02、U02。BUGU 的主线是将多个插件来源中的承诺、执行过程和交付依据接到同一件事上。本场景让观众看到：GitHub 上已经有 PR，不代表原约定已经全部完成；反馈链接仍可能缺失。

## 用户路径

1. 从飞书等来源收录承诺，或者创建人工事项。进入已收录事项的详情。
2. 展开「跟进 PR 提交与反馈」，输入明确的 GitHub Issue 或 PR 链接，确认两个条件。仅支持尚未设置完成条件的事项；已有自定义条件不覆盖。
3. 在同一项目授权 GitHub 和会话来源。PR 描述引用目标 Issue 完整链接，或者直接使用目标 PR 链接。
4. 系统显示「提交目标 PR」已有依据，第二项仍缺「向约定对象反馈同一 PR 链接」。执行会话中声称完成只算过程记录。
5. 反馈到达：原承诺作者在原飞书消息下直接回复同一 PR 链接时自动建立支持关系。其他会话或无法确认对象的消息进入人工核对。
6. 两项依据齐全、没有待确认或相反记录后，由用户点击「核对后确认完成」。业务状态不会自动改为完成。

默认详情展示两项进展、当前缺口和下一步操作。待确认记录逐条处理；来源原文、判断理由和关联历史默认折叠。

## 条件边界

| 条件 | 认可依据 | 不足以证明 |
| --- | --- | --- |
| 提交目标 PR | 已授权 GitHub 连接收到的 open / merged PR；PR 本身是目标对象，或描述明确引用目标 Issue 链接 | AI 说已完成、本地 JSONL 伪装 GitHub、其他项目的同名 PR、关闭且未合并的 PR |
| 向约定对象反馈同一链接 | 同一 PR 的明确反馈消息；原作者在原飞书消息下直接回复，或用户人工核对反馈对象 | 只创建 PR、另一条 PR 的链接、准备/尚未反馈、助手输出、无法确认对象的普通消息 |

本约定不要求 PR 合并、CI 通过、部署或等待外部评审；draft PR 也算已提交。关闭且未合并的 PR 视为需核对的相反记录。本场景的交付评估独立于旧的通用证据状态；不把两项条件充分性冒充为任意自定义事项的通用核验。

## 五类冻结样例

所有例子使用虚构项目 `example/demo`、目标 `https://github.com/example/demo/issues/1`、PR `https://github.com/example/demo/pull/2`。

| 样例 | 输入与过程 | 预期展示及结果 |
| --- | --- | --- |
| 成功 | 原承诺为提交修复并反馈；PR 描述引用 Issue；原作者在原消息下回复「已反馈 PR 链接，请查收」及同一 PR URL | 两项已有依据；核对后才能手动完成；重启保留 |
| 部分完成 | GitHub 已有对应 open PR，只有执行会话的「完成了」 | 1 / 2；下一步反馈链接；无完成按钮 |
| 失败 | PR 后续关闭且未合并，或者用户对目标链接说「提交失败」 | 前者不能满足提交条件；后者保留相反记录待核对；不自动完成 |
| 改期 | 用户对目标链接说「延期到周五提交」 | 提示核对约定，阻止交付确认；用户更新事项截止时间，核对并排除已不适用的相反记录。若改写完成条件，旧场景评估失效，不沿用旧条件结论 |
| 取消 | 用户对目标链接说「取消这次提交」 | 保留待核对记录；用户取消事项后不再允许交付完成操作。仅一条消息不自动取消业务状态 |

## 关联与信任规则

- 先限定同一项目，再匹配完整 GitHub 对象 URL，不以标题近似或同名进行跨项目合并。
- PR、反馈、执行过程关联到已有事项；处理队列不会为已经命中场景的记录再建候选。无匹配记录继续走原候选处理规则。
- 多个事项匹配时都保留候选和原因，不强制选择。确认一次后，保存来源实例＋对象 external ID 的归属，后续 PR 修订沿用选择。被排除的归属不会因重放恢复。
- 人工确认与来源对象映射仅限项目内；不等价于全局账号身份映射或跨项目语义检索。
- GitHub 新修订取更新时间较新的记录；同一时间的矛盾正文不选赢家。普通会话出现不同修订时，原引用不再作为交付证明。
- 来源撤回、撤销授权或插件卸载后依据不可用；暂停采集不等于撤销历史授权。
- 写入核对任务版本、条件版本、人工版本和当前证据摘要；核对时记录发生变化则拒绝陈旧提交。
- 关联动作和人工排除保留审计；自动完成不存在。完成后依据失效会反映在交付面板，不自动重开或改写用户业务状态。

## 交付范围与限制

这是具体的 PR 交付场景，不是通用 LLM 语义关联引擎。只识别完整 `https://github.com/.../issues/N` 或 `/pull/N`，不解析短链、`#123` 或自然语言同义对象。首次启用最多回看项目最近 1000 条记录，最多展示 500 条依据，达到上限明确提示覆盖不完整。关联历史展示最近 50 次。

反馈语言采用保守中文肯定规则；其他措辞可能需要用户重新明确反馈。人工确认反馈意味着用户核对了对象，而不是系统自行识别了所有跨平台收件人。

改写完成条件后保留旧场景与历史并显示失效；本轮不提供旧场景自动迁移到新约定。通用条件编辑、原有证据核验与审计继续可用。导出目前仍采用既有通用任务/证据格式，本轮专用交付面板与关联审计的导出另行补充。

## 路演脚本（约 90 秒）

- 0–15 秒：介绍「承诺在聊天里，执行在编码工具里，交付在 GitHub；我们把它们接成一件事」。打开一条已收录的约定。
- 15–35 秒：展示两个完成条件，切到已有 PR 的状态：只完成 1 / 2，还差反馈。
- 35–60 秒：收到反馈消息；展示系统自动关联，或在对象不确定时进行一次人工确认。两项进展变为 2 / 2。
- 60–80 秒：展开依据，看来自 GitHub 和会话的两条原记录；收起后手动确认完成。
- 80–90 秒：说明插件来源可以扩展；桌宠只作为低打扰提醒的辅助出口。

路演前先完成连接授权、采集和一次预演。演示若使用合成数据须明示；本地测试不访问个人会话、历史或凭据。
