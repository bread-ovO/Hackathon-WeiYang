# BUGU 事件入口一致性与退出验收

本批对应 E03、S04 和 S07。退出验收补齐了本地采集组合场景；S04、S07 仍有事项业务消费者尚未实现的部分。

## 事件与修订

所有收录入口共用同一存储事务。以来源实例、外部对象 ID、修订 ID 判断重复；同一修订的角色、原文或原始发生时间不同会拒绝，事件、作业、上下文和游标全部回滚。新修订正常入队。内部游标上限与插件保持 16 KiB，兼容 HTTP 分页的历史摘要；application 层原有 4 KiB 约束不变。相同输入重复到达不会再登记作业或上下文，但允许记录当前采集游标。

这保证事件层的一致性。后台作业消费者、模型建议提交和事项业务幂等链路仍未接通，因此不能以此宣称“同一事件只触发一次事项变更”已完成。

## 时间与项目范围

SQLite v7 增加 event_contexts，与新增事件在同一事务写入。上下文保留发生时间和宿主接收时间，记录 UTC、纳秒、原始时区偏移及解析依据；原始 source_events 时间不重写，避免破坏修订重放比较。

升级按 500 行分页回填旧记录；旧无效日期保留，标记 invalid_legacy_time，不猜测时区。新记录拒绝无法规范化的时间。

内部 contexts.get(projectId, eventId) 先检查 event_projects 关系，再计算来源、对象和项目共同限定的身份。它标识来源对象，不能把角色或显示名当作人物身份；也没有建立跨来源人物映射。旧协议允许但身份规则不接受的空白或控制字符 ID 保留原值，返回 identity:null 和 invalid_source_identity，禁止调用者据此推断匹配。跨消息的计划对象不能直接使用事件身份替代。迟到计划比较规则尚未接入自动事项更新，因此 S07 保持进行中。

## 退出采集回归

使用隔离目录、虚构 JSONL、真实插件运行时与 SQLite。先成功采集并记录成功时间，重启后在第二次读取进行中主动退出。仅延迟测试文件的读取，观察生产退出路径取消 AbortSignal；读取恢复后，新事件没有落库、成功时间没有提前，重启仍能显示原来的成功时间。

该组合测试覆盖本地 JSONL。它不代表 HTTP 在途退出、物理休眠、所有操作系统的设备验收。测试未读取个人聊天和真实凭据。

## 并发选择模型修复

全量桌面回归暴露既有竞态：后台状态查询等待 worker 时占用修改锁，第二次选择模型会立即收到 PET_UNAVAILABLE。状态查询改用独立的合并 Promise，不占用修改锁；worker 仍串行处理请求，导入、选择和移除之间继续互斥。补可控未完成查询的单测，验证目录选择不会被后台查询挡住。

## 验证

`pnpm check` 通过：包边界、严格类型、1065 项单测、8 组真实 SQLite 集成、19 项桌面测试。默认跳过真实 30 分钟长测与原生鼠标设备用例；桌宠长测已在 PR #88 独立完成，本批未修改帧预算和 WebGL 恢复路径。

覆盖 v2/v3/v4/v6 到 v7 升级、旧无效时间、重复重放、同修订冲突与上下文失败回滚、跨项目隔离、8.6 KiB 和 16 KiB 分页游标及越界拒绝。退出组合回归和再次导入模型流程均通过。
