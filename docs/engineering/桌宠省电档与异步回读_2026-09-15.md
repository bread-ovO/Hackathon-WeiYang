# 桌宠省电档与异步回读

用户反馈 seio 循环动画在 60 FPS 下 CPU 占用偏高。默认改为省电档：空闲 30 FPS，鼠标交互后 4 秒、拖动、气泡展示和显式动作期间 60 FPS；动作时间按实际经过时间推进，不减慢播放速度。右键「动画性能」可切换到始终 60 FPS 的流畅档，选择随窗口偏好持久化。旧配置默认省电。

## 实现

- 每个模型缓存不可变的原生参数 ID → 索引；未知参数继续交给 Cubism 处理，保留虚拟参数语义。
- 128×128 透明穿透图使用 WebGL2 像素缓冲区与 fence 异步回读，最多一个请求在途；未完成时沿用上一张图，不阻塞等待。恢复或销毁会清理资源。初次模型可见性校验仍为一次性同步读取。
- WebGL 错误检查由每帧改为每秒，contextlost 事件仍即时处理；避免不可见提示的逐帧布局读取及重复设置鼠标样式。
- 性能模式通过现有 typed preload 配置接口和主进程原生菜单设置，两端校验可选值。

## 验证与局限

本机 macOS，独立临时工作区，用户提供的 seio-loop 资源，10 秒稳定采样；CPU 来自 Electron 各进程 cumulativeCPUUsage 差值，100% 为一个逻辑核心。没有读取真实聊天或凭据。

| 模式 | 实际 FPS | 桌宠渲染进程 CPU | GPU 辅助进程 CPU | 全应用 CPU |
| --- | ---: | ---: | ---: | ---: |
| 改前始终 60 FPS | 59.98 | 28.88% | 10.03% | 39.48% |
| 改后省电空闲 | 30.07 | 18.90% | 6.62% | 26.21% |

空闲总 CPU 下降约 34%。保持 60 FPS 的首轮优化测得总 CPU 仍约 41%，没有证据表明缓存/异步回读能显著降低总 CPU；主要成本在 Cubism Core 模型计算，收益主要来自空闲帧率策略。短样本会受其他应用、动作阶段、鼠标移动影响，不承诺所有模型同比例下降。GPU 辅助进程 CPU **不是 GPU 利用率**，本轮未获得可靠的进程级 GPU 百分比。

定向验证：参数/回读、帧率预算、透明命中、原生菜单、窗口持久化、主进程边界；Hiyori 空闲/活动帧率、WebGL 恢复、渲染进程崩溃隔离；seio 自定义性能基准。基准通过 `PET_BENCH_MODEL_DIRECTORY` 显式指定模型，`PET_BENCH_MODE=smooth` 可测流畅档，`PET_BENCH_PROFILE=1` 可采样渲染器 JS CPU 栈。
