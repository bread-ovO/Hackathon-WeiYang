# S05 持久作业与租约恢复

2026-09-13，基于 upstream/main 9bcaa1f。存储层实现完成，任务进入待验收；不代表后台模型处理链路完成。

## 实现

`store.jobs` 提供 claim、renew、complete、fail、get。继续使用 SQLite v1 已有 jobs 表，不需要改写用户数据或升级 Schema。

- `claim` 在 BEGIN IMMEDIATE 事务内选择并更新一条到期作业，跨连接竞争只允许一次领取。领取递增 attempt，作为本次执行代次。
- 租约 30 秒，可续期；`id + attempt + running + 未过期租约` 同时匹配才允许续租、完成或失败。重新领取后的旧执行者和已过期执行者都会被拒绝。
- 显式可重试失败采用 1 秒、2 秒退避，最多 3 次总尝试（包含首次）。不可重试失败直接终止。每次失败只存枚举错误码，不保存异常原文或凭据。
- 崩溃后租约到期可重领；最后一次尝试崩溃后，在下一次 claim 时标为 failed/LEASE_EXPIRED，不无限重试。完成清空租约、下次执行时间和失败码。
- 时间可注入，方便确定性测试。诊断通过 get 查询持久化 state、attempt、leaseUntil、nextRun 和 errorCode。

## 验证

完整 `pnpm check` 覆盖包边界、类型、14 项单元测试、构建、存储集成和桌面集成。新增队列集成覆盖两个真实 SQLite 连接竞争、续租、边界时刻到期、旧执行者完成/续租/失败拒绝、退避、永久失败、重试耗尽，以及真实子进程 SIGKILL 后重开数据库恢复。测试只用临时目录与虚构事件。

## 边界

尚无后台消费循环与真实模型处理器；未来处理器只在成功产生持久化结果后调用 complete。外部模型请求等副作用仍需独立幂等键，租约不提供 exactly-once 保证。处理器必须按需续租，并在失去租约后丢弃结果；多表业务提交需与作业完成设计同一事务，不能先标记 done 再保存结果。
