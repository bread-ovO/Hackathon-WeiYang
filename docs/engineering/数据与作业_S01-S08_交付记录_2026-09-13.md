## 2. 关键运行规则

- 来源登记不授予权限。宿主显式 grant 后产生 scopeEpoch；撤权和重新授权使旧作业失效，旧事件不能自动重新获取授权。人物映射既校验版本/项目，也检查两侧来源仍有效。
- 成功接收返回回执后才可继续拉取。相同回执先于游标 CAS 判断；当前授权仍先校验。每个 stream 自动保留最近 1,000 个回执，清理后的旧 batch 不能回退检查点。
- 新事件获得稳定根作业身份。业务提交先校验 task/criteria/manual/mapping/generation，最后再次验证 lease；决定、修订、搜索投影、逻辑 outbox、幂等结果和 job.done 全部提交或回滚。
- 每次领取消耗尝试预算。停止执行器保留可重试工作；磁盘暂停条件消失可重新领取，墙钟异常暂停需显式恢复。永久失败可在健康状态中看到计数；错误诊断仅记录有界错误码。
- 归档不代表完成；忽略不代表取消；人工完成不伪造充分证据。条件修订、来源撤权或墓碑使证据投影保守失效，保留业务状态和历史决定。自动完成默认关闭，测试中的开启只验证证据提交门槛，不代表语义核验已实现。
- 不确定项目/来源范围返回 `scope_unknown`。一个事项关联多个来源时，候选调用方必须可见全部关联范围；每条精确、FTS 和回退路径均遵守相同条件。
- 未配置业务 handler 时，核心不领取或伪造完成作业，健康回复显示 `NO_HANDLER`。当前桌面 handler 注册表为空，真实事项列表/编辑仍未接入这些仓储；示例体验仍仅保存在窗口内存。

## 3. 初始资源参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 单事件 / 整页 | 256 KiB / 2 MiB | 完整 JSON 的 UTF-8 字节；Schema 另限制正文 65,536 字符 |
| 每页条数 / 游标 | 100 / 4,096 字节 | 超限拒绝整页，原检查点不动 |
| 队列高 / 低水位 | 10,000 / 8,000 | 未完成作业计数；回执重放和重复事件不重复占额 |
| 受管磁盘 / 卷预留 | 512 MiB / 16 MiB | 写入按估算放大八倍且至少预留 64 KiB；实际 SQLite 写满仍可能发生，事务负责回滚 |
| 并发 / 租约 / handler 超时 | 2 / 60 秒 / 120 秒 | 心跳默认每 20 秒；实际接入后按负载校准 |
| 最大尝试 / 退避 | 5 / 1 秒至 60 秒 | 指数退避带抖动；进程崩溃也消耗预算 |
| 检索候选 / 回退 | 20 / 同项目近 90 天最多 200 条 | 回退返回原因，不能把近期候选视为语义命中 |

额度设置通过三个命名 bridge 方法中的 `updateCapacity` 执行，另两个为 `health`、`resumeSource`；请求和回复均由 Schema 校验。不暴露原始 IPC、SQL、数据库对象、文件路径或凭据。容量探测和备份只统计应用拥有的路径，拒绝符号链接；这不是操作系统级硬磁盘配额。

- 单元测试：`tests/unit/data-foundation.test.ts` 与既有 foundation 测试。
- SQLite 测试：`tests/data-foundation/integration.ts`、`fixtures.ts`、`crash-worker.ts`，由 `pnpm test:storage` 实际打包执行，纳入 `pnpm check`。
- 冻结检索集合：`tests/data-foundation/search-cases.json`，版本 `synthetic-holdout-v1`；每组 30 个正例、10 个负例，共 120 例。测试不使用负例回退提高正例召回。
- 桌面测试：`tests/desktop/app.spec.ts`。真实核心健康、额度持久化、核心进程恢复、typed bridge 白名单及示例隔离通过；设置页宽/窄截图已人工查看，无横向溢出。测试产物位于 `test-results/`，Playwright 的清理范围限定为其子目录，避免删除此前存储报告。

正例宏平均 Recall@20 = 100%，三个语言组各为 100%，正例漏召回 0/90。30 个负例共产生 524 条未相关候选，其中 26 例触发近期回退、4 例因拆词交集产生 FTS 候选；因此不能用召回率声称语义精确率达标，下游必须识别 `fallback` 并重新核验。当前分词版本为 `zh-bigram-code-v1`。

本次 1 万事项基线：重开连接后首个查询约 17.4 ms，暖查询 P50 25.0 ms / P95 26.6 ms；索引重建约 1.13 秒，完整合成写入约 6.7 秒，数据库约 17.89 MiB。这里“冷”仅指连接重开，未清除操作系统缓存；本机后台负载未受控。这是可复现测量方法的单次基线，尚未冻结性能预算，不判定性能达标。

## 5. 剩余边界与接入顺序

下一步由真实来源适配器调用 `ingestNextPage` 并遵循接收回执；业务流水线通过 `JobHandler` 返回经过契约定义的 proposal，由宿主调用 `commitJob`；人工 UI 通过命名应用入口提交，不能直接写库。这些接口已经有真实持久化与故障测试，但实际来源和推理尚未实现。

仍需按原清单完成 F/L/G 授权来源、A/V/H 提取/关联/核验及人工纠正、Q02 加密/Q03 授权/Q05 删除、U03 真实来源暂停页和 T 系列负载联验。特别是跨来源游标有效期、缺失修订覆盖、系统休眠、自然语言日期歧义、迟到反证语义和真实用户候选质量，不能从合成测试外推。

迁移 v2 不可直接降级使用旧程序；迁移前的一致性备份保留在数据库同级受管 `.backups` 目录。恢复需要关闭应用并由后续恢复流程显式选择备份，本轮未添加恢复备份 UI。未签名 `.app` 只证明本地打包流程，不代表公开发行、签名或公证已完成。


## 6. 测试加固复验（2026-09-13）

用户要求进一步做好测试后，新增 12 组存储场景及 4 个流式读取单元测试，并扩展真实 Electron bridge 的拒绝路径。以下缺陷先由新增测试复现，再修正实现；没有通过放宽断言绕过问题。

| 复现问题 | 修正 | 回归证据 |
| --- | --- | --- |
| 墙钟在首次心跳前回拨，快速 handler 仍提交了 1 个事项，预期为 0 | handler 返回时检查时间；存储续租/保存/提交也拒绝早于本次领取时间的时钟。当前 owner/token 可记录 CLOCK_CHANGED 暂停，不能写业务结果 | hardening：快速返回、直接存储接口、暂停诊断；已有过期及旧 token 用例持续通过 |
| 分词版本升级重建失败后，searchReady 仍为 true | 健康与检索共用就绪判定，同时核对索引状态和当前分词版本；失败维持降级，后续成功重建恢复 | hardening：故障重建、降级检索、重新打开恢复 |
| 已取消的读取仍读了一次；等待下一块数据时取消超时 | 读取前检查取消；等待块时与 AbortSignal 竞争，请求迭代器清理，不等待阻塞的清理过程 | 4 个 transport-hardening 测试：逐字节 UTF-8、无效尾序列、预取消、创建迭代器时取消、阻塞读取取消 |

补充的可靠性测试：

- 4 个独立 Electron Node 子进程在同一屏障后竞争同一游标，只有一页提交，另外三页返回 STALE_CHECKPOINT。
- 4 个独立进程竞争同一作业，只有一个 lease，attempt 与尝试记录均只有 1 条。
- 保存 proposal 后真实 SIGKILL；下一进程接管并复用结果，handler 不重跑，只有一次业务提交。
- 可控 handler 等待期间人工完成，迟到建议不改写人工决定；等待期间撤权并重新授权，旧作业继续 cancelled，不能重获资格。
- 人物映射另一侧来源撤权，即使该侧未直接出现在事件输入中，也阻止提交。
- 逐一缺失事件和 provenance 必填字段，事件、作业、回执、游标均无写入。
- 另一连接保持打开时，迁移备份包含已提交 WAL 内容；旧库存在孤立外键时，迁移失败并保留 v1。
- 核心重启后保留已保存额度；真实 renderer 发出的过小额度、多余字段和 NaN 请求均拒绝，已保存额度不变。

最终 `pnpm check` 全通过，日志见 [完整检查日志](evidence/S01-S08_2026-09-13/check.log)。修复后重新执行 `pnpm package:dir` 通过，见 [打包日志](evidence/S01-S08_2026-09-13/package.log)。39 组存储报告包括原 27 组和新增 12 组；22 个单元测试包括原 18 个和新增 4 个。桌面测试仍为一条多步骤端到端用例，并不把每个断言另算成用例。
