## 语义与边界

活跃度来自人工决策、规则处理、引用冲突/确认、来源关联和计划评估的记录时间；不把无更新当作完成。筛选列表显示已安装/已授权的来源，历史已卸载插件的记录仍可从事项引用查看。空列表显示清除筛选，不填充示例。

截止解析只接受有明确承诺或截止标记的日期，不把「提交周五评审所需报告」误认成周五截止。以原消息显式 UTC 偏移解释日期；无时刻取当日末尾，含糊的「下午」、多个日期、可能/左右等保留为空。UTC 日志无法恢复原作者未提供的本地时区，候选始终可核对原句并修改。新规则不重算已处理的历史事项；旧 v1 决策仍可在时间线和导出中读取。

合并由 SQLite 单一事务执行，检查两条事项的项目与三个版本，防止并发覆盖。来源必须是未归档且未忽略的事项；目标标题、业务状态、负责人、截止时间保持原值。相同文本的条件合并，来源条件 ID 映射到目标新条件版本；当前条件的人工证据和所有候选原文引用复制到目标，原链接及历次条件仍留在原事项。复制的有效/未知证据降为待核验，原失效证据保持失效，目标证据充分度重置为未知。引用修订/撤回重新核对。两端记录人工合并决策，来源归档并只读，旧 ID 可找到最终目标。旧来源的历史条件和历史证据通过合并来源链接读取，绝不删除或改写。

账户监听仅限当前凭据在 GitHub REST API 返回的可访问范围。未授权私库无法枚举，不声称全网或整个 GitHub 账户的不可见内容均已覆盖。存储检查点包含仓库分页、仓库序号、内容类别和内容分页；每批最多 51 个观察，持久事务提交后才前进。每轮重新发现仓库；每次请求读本机保险库，核对账户 ID 与仓库 ID，禁止转向其他站点。403/404 权限失败显示错误及受影响仓库，保留进度，用户修复权限后重试；429/限流共用持久凭据冷却，暂停/撤销使在途批次失效。失败不会提交半个分页。完整扫描是周期快照，可再次发现更新；不是保留每个瞬时修改/已删除评论的 Webhook 历史系统。单个无权限仓库会阻止本轮继续，界面明确提示修复授权。

GitHub 依据：[可访问仓库](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user)、[PR](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)、[Issue 评论](https://docs.github.com/en/rest/issues/comments#list-issue-comments-for-a-repository)、[代码审查评论](https://docs.github.com/en/rest/pulls/comments#list-review-comments-in-a-repository)。Kimi 格式与样例边界见 [会话格式说明](../plugins/session-formats.md)。

## 本地验证

测试使用隔离数据库、虚构会话和注入 HTTP 响应，不读取个人聊天、真实凭据或生产数据库。定向覆盖：发生时间/歧义日期、Kimi 角色/坏文件/版本/原文、合并回滚/旧 ID/条件/证据/重启、组合筛选/分页、GitHub 身份与 URL 校验/分页/重放/限流/权限/暂停。E2E 仅运行 five-requirements、workspace、session-import、github、security；未跑全量 E2E。

真实 Kimi 客户端导出与 GitHub 私有仓库权限组合，仍需要用授权样本做外部验收；多维表先标待验收，不将模拟响应测试描述为真实账户验收。

本批结果：248 项定向单测、10 组存储集成测试、5 个受影响桌面 E2E 用例通过；类型检查、构建和包边界检查通过。宽窗口与 980px 窄窗口截图已检查。
