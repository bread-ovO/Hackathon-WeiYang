# 第九批：连接轮询与恢复

本批修复连接器与现有插件的恢复行为，不把辅助函数存在等同于完整来源接入。

## 已上线插件

临时 HTTP 超时和网络请求失败按采样间隔进行指数退避，连续三次失败后暂停；地址越权、重定向、非法响应和不确定的数据库提交不作为网络错误盲目重试。只有事件事务成功才更新游标和最近成功时间。停止时取消在途读取及已计划重试。

连接页展示最近成功时间、重试次数和下一次重试时间，每 15 秒刷新运行概况，不恢复旧试运行确认。重试次数及额度为当前进程内状态，重启会重置；正式来源游标与事件去重仍由 SQLite 持久化。

## 轮询器

`SourcePoller` 在拉取完成后再次检查取消，取消后不调用 sink；sink 已开始且最终成功时保留其已提交游标。sink 拒绝不会重新拉取变化中的页面，调用方应从持久化游标恢复。加入重复游标检查、页预算、失败上限、同实例并发拒绝和 abort 监听器清理。

支持服务端 `retryAfterMs`，不会被普通退避上限缩短。诊断仅返回计数与时间戳。该轮询器目前仍是飞书分页接口，不声称已接入专用来源宿主。

## 飞书与 GitHub 适配器

适配器不再内置裸 fetch 或允许任意 baseUrl，必须接收宿主提供的 `SourceHttpTransport` 能力。域名固定，响应作为不可信数据校验，禁止把 Token 放入 URL 或错误信息。

飞书校验 HTTP 与业务状态、页上限、毫秒时间戳、发送者类型及分页游标；未知/匿名发送者不冒认为用户。官方说明见[飞书历史消息与字段说明](https://www.feishu.cn/content/mtb6n3ah)。空正文删除修订只保留源记录语义，不代表已完成证据失效。

GitHub 使用 state=all，校验选定仓库、PR URL、创建/关闭/合并状态及 head/base 元数据，按 Link 获取下一页。缓存按完整 URL 保存 ETag（最多 32 个 URL、8 MiB），304 复用独立副本；429/403 返回受限的重试信息。规则依据：[PR API](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)、[Link 分页](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api)、[条件请求和限流建议](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。数字分页不是服务端快照，仍需周期重扫与持久化去重。
