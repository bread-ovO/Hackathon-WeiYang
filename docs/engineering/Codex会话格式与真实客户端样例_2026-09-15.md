# Codex 会话来源与真实客户端样例（D03 / L05）

选择 Codex 本机授权会话作为当前基准来源。常规接入读取授权目录中的 rollout JSONL；新增对真实 CLI 会话捕获文件的显式兼容，方便使用新建样例验收而不读取个人聊天历史。

## 两种格式不能混称

| 输入 | 时间与角色 | 版本处理 |
| --- | --- | --- |
| Codex rollout `response_item` | 文件 timestamp；message.user / assistant；function_call_output / custom_tool_call_output 作为 tool | 无独立稳定的官方版本保证；只接受明确支持的记录/内容类型；未知类型报错 |
| BUGU `codex_exec_capture` v1 | user 为包装器实际送入 stdin 的文字；assistant/tool 为实际 stdout 事件；timestamp 为包装器收到事件的本机时刻，保留本机 UTC 偏移 | formatVersion 必须是 1；目前验收 Codex CLI 0.154.0-alpha.6.2 的 agent_message 与 command_execution |

`codex exec --json` 的原生输出没有用户输入事件和逐条墙钟时间，所以捕获文件明确增加外层封装，没有冒充原始 rollout。捕获时刻适用于该新会话；不能拿旧的 stdout 文件补上“今天”作为原消息时间。此样例验证真实客户端捕获分支；原生 rollout 分支另由既有格式契约和目录接入测试覆盖。[官方非交互模式](https://developers.openai.com/codex/noninteractive/)

## 样例来源

`tests/fixtures/codex-native/capture.json` 保存本机实际 Codex 调用输出，`session.jsonl` 仅为每条原始事件添加 v1 时间封装（capture.json 的 UTC 时刻与 session.jsonl 的 +08:00 表达是同一瞬间，captureTimezone 记录 Asia/Shanghai），不修改助手或工具文字。样例对话为本次验收新造的数据，工具只执行 `/bin/zsh -c pwd`，没有读取任何个人会话；凭据由原 CLI 自行使用，测试不读取、复制或导出凭据。

新建会话使用 `--ephemeral --ignore-user-config --ignore-rules --sandbox read-only`，关闭 hooks、apps、web_search，并禁用登录 shell；工具调用仅用于取得这次隔离目录的环境信息。临时目录里的路径出现在样例原文中，不是业务数据。`--ephemeral` 不持久化会话文件，因此使用 stdout 捕获，不去个人 sessions 目录搜寻新文件。[官方模式说明](https://developers.openai.com/codex/noninteractive/)

复现（仅在明确允许调用真实模型时运行）：

```sh
BUGU_EVAL_LIVE=1 node tests/evals/capture-codex.mjs /tmp/bugu-new-codex-capture
```

输出为真实 user / assistant / tool / assistant 四条可收录事件以及会话元数据。保存版本、原文和时间用于回放。

## 接入边界

- 常规授权目录、增量游标、项目隔离沿用现有实现。Normalizer 从 `codex-session@3` 升至 `@4`，触发重扫；旧 ordinal / offset ID 保留，已有消息仍按原 ID / revision 去重。
- 新版保留工具输出以便溯源，但 AI 提取上下文仅包含 user / assistant，工具中的承诺不成为待办。
- 未知捕获版本、损坏 JSON、未知类型明确报错，单个来源错误不阻塞同项目另一正常来源。
- 角色、文本、时间及大小先校验，模型输出再校验结构与逐字引用；收录为候选，不自动标记业务完成。
- 此验收未宣称所有未来 Codex / Claude / Kimi 格式均兼容；Kimi Wire 仍按其原有版本白名单处理。
