# Q01 宿主凭据保护

设置页现在支持通过原生文件选择器导入单行 Token、查看名称/域名/用途和移除本机凭据。renderer 不接收文件路径、密文或明文，也没有解密接口。原始凭据文件由用户管理，导入后不会删除。

主进程使用 Electron safeStorage 系统加密，独立写入 userData/credentials/credentials.json，不写入事项 SQLite。无可用系统加密时拒绝导入；Linux 的 basic_text 和 unknown 后端被拒绝。密文绑定引用 ID、名称、域名、用途与创建时间，宿主读取须匹配域名和用途。

文件导入限制为 8 KiB、严格 UTF-8、单行 Bearer Token；拒绝符号链接、非普通文件和读取过程中的文件替换。保险库限制 128 条凭据，以 0600 临时文件、同步和原子替换发布；损坏数据拒绝读取，不自动重置。移除仅影响本机引用，不会撤销服务端 Token。

## 验证

本机 macOS 验证使用隔离目录和虚构 Token，系统 safeStorage 实际加密可用；导入、取消、重启解密、移除及 renderer 仅接收元数据均通过。单测覆盖契约、文件输入、存储损坏、域名/用途隔离、原子写入和并发。桌面用例还检查用户目录文件与进程输出不含虚构 Token。

## 范围

当前是凭据基础设施，未连接 OAuth、模型请求或 HTTP 插件授权。P03/P04 仍需把凭据引用绑定到已授权来源，由宿主在发送时解密。事项数据库仍未加密；内存中的明文生命周期受 JavaScript 垃圾回收管理，不能保证立即清零。Windows/Linux 的系统后端尚未在本机验证。
