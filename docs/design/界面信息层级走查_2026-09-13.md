# 界面信息层级走查

本轮针对“首屏信息密度高、配置全部摊开、图标位置不一致”修改实际桌面界面。

| 页面或部件 | 原问题 | 修改 |
| --- | --- | --- |
| 连接 | 首屏串联所有表单、运行指标和未来能力 | 保留快速体验与三张预置来源卡片；点击卡片才显示配置；扩展插件、采集整理按需展开；删除占位入口和重复说明 |
| 设置 | 诊断、凭据、桌宠、语音混排成长页 | 按外观、事项提醒、声音、凭据、运行状态分组，默认收起；诊断不再占据首屏 |
| 事项详情 | 审计功能排在编辑之前，长内容撑出面板 | 常用编辑先展示，关联/改期/历史收起；详情正文独立滚动，关闭按钮固定在顶部 |
| 图标 | 直接子元素选择器遗漏 Kumo 的 contents 包裹层 | 按实际结构统一图标 16px、居中与不收缩，主要控件间距 8px |
| 页面切换 | 原生 disclosure 的展开状态可能被 React 复用到另一页面 | 为不同页面提供独立 key，避免设置与连接之间泄漏展开状态 |
| 键盘操作 | 配置关闭后焦点可能留在隐藏节点 | 原生 Enter/Space 展开；从来源表单收起时，焦点返回对应卡片按钮 |

保持原有读取授权、编辑、保存、人工复核和原文查看能力。折叠内容保留挂载，收起再展开不会丢失配置草稿。涉及来源撤回和引用待复核的原文提示仍保留在事项主要依据区域。

验证覆盖 1140px 和 880px 宽度下的连接、设置与事项详情；检查水平溢出、图标中心、配置显隐、键盘开合和草稿保留。现有来源配置、插件安装、事项编辑与审计流程的桌面测试同步通过用户可见入口展开配置。
